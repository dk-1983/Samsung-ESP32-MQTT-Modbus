# Обзор, веб-пульт и команды питания — 0.4.6

Главная страница `/` показывает температуру помещения, уставку, питание, режим
и отдельные состояния контроллера, UART, связи с кондиционером и MQTT.
`/control` добавляет температуру, режим, скорость включая Turbo, оба качания
и пресеты. Экспериментальные функции и сырые ответы доступны по ссылке
«Открыть расширенный пульт» на порту 8080.

## Питание

Кнопки «Включить» и «Выключить» отправляют только поле питания Samsung UART.
Режим, температура, скорость, качание и пресет не включаются в эту команду.
Включение не выбирает охлаждение или другой режим. Выбор режима в новом веб-пульте
также не меняет питание: это отдельные действия.

Значения на странице берутся из обратной связи, не из отправленной команды.
HTTP 202 означает принятие к отправке, а не подтверждение исполнения. Показатель
«Последняя команда контроллера» отображает pending / confirmed / timeout / cancelled;
он общий для всех источников управления, включая MQTT и Modbus.
Неизвестное или устаревшее поле отображается как «—». При потере HTTP-связи
кнопки блокируются. Кнопки также недоступны при выключенном UART, устаревшем
CORE, обновлении или ожидающей команде. Сервер повторно проверяет условия записи.

## MQTT

В Home Assistant MQTT Discovery добавлены две кнопки: **AC power on** и
**AC power off**. Это команды без собственного состояния. Фактическое состояние
по-прежнему читается из climate и диагностики **AC feedback fresh**.
Так при загрузке не публикуется выдуманное состояние питания новой сущности.

Топики при стандартном префиксе:

| Команда | Topic | Payload |
|---|---|---|
| Включить | `samsung-s3/button/ac_power_on/command` | `PRESS` |
| Выключить | `samsung-s3/button/ac_power_off/command` | `PRESS` |

При изменении префикса заменить `samsung-s3` на настроенное значение.
Точные топики также содержатся в Discovery. Отправлять **без retain**.
Кнопки используют штатный ESPHome MQTT, который не фильтрует retained-команды:
сохранённое брокером сообщение может повториться после переподключения.
Отдельного автоматического восстановления состояния питания в обработчиках нет.
Не использовать retained-команды для управления кондиционером.

Веб и MQTT вызывают общий `set_power(bool)`, который формирует единственное
поле `POWER` и использует существующую проверку свежести, занятости и UART.
Отказ MQTT-команды записывается в журнал; нажатие кнопки HA не является
подтверждением изменения питания. Старое управление через MQTT climate сохраняется.

## HTTP API

- `GET /control/status`: авторизованный JSON, неизвестные поля = null;
  `power`, `target`, `mode`, `fan`, `swing`, `preset`, `room`, состояния связи,
  `busy`, `can_command`, результаты команд.
- `POST /control/set`: авторизация, текущий CSRF `token`, `field`, `value`.
  Один параметр за запрос. `field=power`, `value=1` включает; `value=0` выключает.
  Поля target/mode/fan/swing/preset принимают нормализованные UART-значения
  (не заводские коды Modbus): target 16..30, mode 1 cool / 2 heat / 3 dry /
  4 fan / 5 auto; fan 1 low / 2 medium / 3 high / 4 auto / 5 turbo;
  swing 0 off / 1 vertical / 2 horizontal / 3 both; preset 0..8.
- Ошибки: 400 — неверное поле/значение, 401 — нет авторизации,
  403 — неверный token, 409 — сейчас нельзя отправить команду.

## UART-мост (0.5.0)

Веб, MQTT и Modbus используют тот же общий submit/set_power. Подтверждение
команды теперь требует собственного ответа чтения, а штатные уведомления
обновляют отображаемое состояние. Ответ busy возможен также при незавершённой
штатной транзакции; отклонённая команда не ставится в очередь и не повторяется.
Страница About содержит диагностическую строку моста и скорости всех трёх UART.

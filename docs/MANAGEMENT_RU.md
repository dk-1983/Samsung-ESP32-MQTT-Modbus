# Настройки и GitHub OTA — Samsung-ESP32 0.4.1

[English](MANAGEMENT.md)

## Локальное управление

Порт80 — страницы `/mqtt`, `/modbus`, `/updates`; веб-пульт и его REST API теперь
на8080. Локальное ESPHome OTA остаётся на3232. После загрузки0.4.0 старые скрипты
HTTP должны обращаться к8080; адреса Modbus соответствуют карте0.3.0.
Пароли страниц одинаковые. При первой локальной загрузке0.4.0 сохраняются web/OTA/AP
пароли из secrets.yaml; далее используются сохранённые значения, включая после GitHub OTA.

На `/mqtt` checkbox разрешает соединение с брокером. Пустое поле нового пароля
сохраняет прежний; отдельный checkbox удаляет пароль. MQTT и HA discovery выключаются
независимо. Начиная с 0.4.2 каждое сохранение MQTT-настроек вызывает
перезапуск через 2 секунды: это пересоздаёт клиент с новым брокером и паролем. После перезапуска UART снова monitor-only.
Топики и discovery остаются ESPHome, а не Haier `/set/<поле>`.
Уже сохранённые брокером discovery-сообщения не удаляются при снятии checkbox.

На `/modbus` checkbox RTU и TCP независимы. Изменения действуют сразу; существующие
TCP-соединения закрываются. Скорости:9600/19200/38400/57600/115200, формат8E1.
Unit1–247. Выключенный RTU не отвечает, выключенный TCP не слушает502.
Диагностические флаги2479 отражают выбранные состояния транспортов.
Ни один из checkbox не разрешает UART автоматически.

Для первоначального Wi-Fi остаётся ESPHome captive portal на8080. Подключившись
к Samsung-Setup, открыть `http://192.168.4.1:8080/`; ссылка «Настройка Wi-Fi (AP)»
также ведёт туда. Основной портал настроек на80 доступен и при активной AP.

## Обновление

Источник: `https://raw.githubusercontent.com/dk-1983/Samsung-ESP32-MQTT-Modbus/main/releases/stable.json`.
Профиль: `samsung-s3-n16r8-v1`. Образ загружается из Releases этого же репозитория.
Автоматическая установка по умолчанию разрешена, как в Haier; checkbox запрещает
установку, но оставляет проверку. Проверка после старта примерно через минуту,
далее раз в6часов с небольшим случайным сдвигом. Нужны сеть и синхронизированное время.

Перенесены ECDSA P-256 подпись манифеста, HTTPS с проверкой сертификата, проверка
профиля/размера/SHA256/ESP32-S3, отдельный OTA-раздел, подтверждение загрузки и откат.
Новая загрузка считается здоровой после45с работы локальных служб и сети;
сохранённый trial позволяет вернуться к предыдущему слоту при следующем неудачном
запуске или по таймауту. Это пока перенесённый код, а не выполненный тест отката Samsung.
Ключ доверия — тот же открытый ключ издателя4vrs, что в Haier; закрытый ключ не копируется.
Профиль и URL Samsung отделены от Haier, поэтому манифест Haier не принимается.

Локальный OTA и GitHub worker согласованы: worker ждёт разрешения основного цикла;
на время записи GitHub локальный OTA приостановлен. Настройки транспортов во время
GitHub операции не изменяются; запрет обновления можно применить и во время загрузки.

## Релиз

1. Первую0.4.0 установить локальной приватной сборкой, чтобы сохранить персональные
   пароли в NVS. Публичный OTA не предназначен для первичной прошивки пустой платы.
2. В GitHub запустить workflow `Prepare public OTA artifact`. Он использует только
   `release.defaults.yaml`, проверяет чистоту дерева и формирует OTA-образ без личных паролей.
3. Скачать artifact, проверить на стенде. Установить зависимости `requirements-release.txt`.
4. Подписать: `python tools/sign_release.py --build <artifact-directory> --key <private-P256.pem> --out releases/stable.json`.
   Инструмент проверяет соответствие ключа открытому ключу прошивки.
5. При публикации создать тег/Release `v<version>`, загрузить OTA-файл из artifact,
   затем опубликовать подписанный `releases/stable.json` в main.

Предрелиз v0.4.1 установлен через подписанный тестовый канал GitHub поверх 0.4.0.
Проверены загрузка, установка, сохранение настроек/паролей и подтверждение загрузки.
Стабильный канал ещё не опубликован: отсутствие stable.json даёт HTTP404 при
обычной проверке обновления, но не отменяет успешную установку прошивки.

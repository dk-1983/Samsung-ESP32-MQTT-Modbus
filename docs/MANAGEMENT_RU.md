# Настройки и GitHub OTA — Samsung-ESP32 0.4.2

[English](MANAGEMENT.md)

## Локальное управление

### Wi-Fi (0.4.5)

`/wifi` показывает SSID, IP, MAC станции, сигнал в dBm, канал и состояние
точки настройки. `/wifi/reset` — отдельная страница удаления только сохранённой
сети. Перед сбросом нужно знать текущий пароль Samsung-Setup. После подтверждения
контроллер удаляет запись сети и перезагружается через 2 секунды; MQTT, Modbus,
web/OTA/AP-пароли и настройки обновлений сохраняются.

Подключитесь к Samsung-Setup и откройте `http://192.168.4.1:8080/` для ввода
новой сети 2,4 ГГц. После явного сброса старая сеть не восстанавливается автоматически.
При обычной потере связи точка настройки запускается примерно через 10 секунд;
это не удаляет сохранённую сеть.

Авторизованный GET `/wifi/status` возвращает только информацию о соединении,
без паролей. GET `/wifi/reset` ничего не удаляет. POST требует авторизацию,
CSRF `token` и `confirm=RESET_WIFI`; блокируется во время OTA, перезапуска
или pending-команды AC. Запись удаляется адресно из NVS, общий сброс не вызывается.
Сборка требует provisioning через captive portal без вшитых station networks;
это проверяется валидатором конфигурации. Формат ключа соответствует закреплённой
версии ESPHome и должен перепроверяться при её обновлении.

На рабочем стенде проверяются чтение и защита запросов. Реальное удаление сети
и повторное подключение требуют отдельной проверки с доступом к Samsung-Setup.

### Пароли (0.4.4)

Страница `/settings` позволяет независимо изменить пароль веб-интерфейса
(пользователь `admin`, порты 80 и 8080), локального OTA и точки Samsung-Setup.
Для каждого нового пароля требуется повторный ввод. Пустые поля сохраняют
текущее значение. Новые web/OTA-пароли: 16–64 печатных ASCII-символа без пробелов;
точка настройки: 8–63. Существующие web-пароли от 8 символов продолжают работать.

Все поля проверяются перед записью; при ошибке ни один пароль не меняется.
После успешного изменения плата перезагружается через 2 секунды. Если фактически
ничего не изменилось, запись и перезагрузка не выполняются. Пароли сохраняются
одним блоком NVS и переживают OTA. Текущие значения не выдаются через API и не
подставляются в форму. После изменения веб-пароля повторный вход — с новым паролем.
После смены OTA-пароля для следующих локальных загрузок нужен новый пароль;
локальный `secrets.yaml` на компьютере автоматически не изменяется.

Домашний Wi-Fi, MQTT и проверка подписи GitHub-обновлений не затрагиваются.
Во время OTA, запланированного перезапуска или ожидающей команды AC смена
паролей блокируется. Это смена паролей при наличии доступа, а не восстановление
забытого пароля; механизма восстановления пока нет.

API: `GET /settings/config` возвращает только `credentials_ready`.
`POST /settings/config` требует авторизацию, CSRF `token`, пары
`web_password`/`web_confirm`, `ota_password`/`ota_confirm`,
`setup_password`/`setup_confirm`. Пустая или отсутствующая пара сохраняет пароль.
Лишние и повторяющиеся поля отклоняются. Ответ содержит только `changed` и `restarting`.

### О системе и перезагрузка (0.4.3)

Страница `/about` показывает версию, имя, IP, MAC Wi-Fi, время работы,
внутреннюю RAM, PSRAM и Flash. Wi-Fi, MQTT, UART, свежесть данных кондиционера
и выбранные транспорты Modbus отображаются отдельно. MAC — адрес станции Wi-Fi,
подходящий для закрепления IP в DHCP. Технические данные доступны в раскрываемом блоке.

Кнопка «Перезагрузить» требует подтверждения. Настройки сохраняются;
страница ожидает новый запуск и обновляется после восстановления связи.
Во время OTA или ожидающей подтверждения команды AC перезапуск отклоняется.
После загрузки UART включается автоматически. При смене IP страницу нужно
открыть по новому адресу.

API: `GET /system/status`, `POST /system/restart`. Оба требуют авторизации;
POST дополнительно требует текущий CSRF `token` и `confirm=RESTART`. GET не
выполняет перезагрузку. Диагностика не содержит паролей; `boot_id` меняется
при запуске, `uptime_s` показывает длительность работы. `storage_ok` отражает
результат инициализации хранилища, а не непрерывный тест памяти.

Порт80 — страницы `/mqtt`, `/modbus`, `/updates`; веб-пульт и его REST API теперь
на8080. Локальное ESPHome OTA остаётся на3232. После загрузки0.4.0 старые скрипты
HTTP должны обращаться к8080; адреса Modbus соответствуют карте0.3.0.
Пароли страниц одинаковые. При первой локальной загрузке0.4.0 сохраняются web/OTA/AP
пароли из secrets.yaml; далее используются сохранённые значения, включая после GitHub OTA.

На `/mqtt` checkbox разрешает соединение с брокером. Пустое поле нового пароля
сохраняет прежний; отдельный checkbox удаляет пароль. MQTT и HA discovery выключаются
независимо. Начиная с 0.4.2 каждое сохранение MQTT-настроек вызывает
перезапуск через 2 секунды: это пересоздаёт клиент с новым брокером и паролем. После перезапуска UART включён.
Топики и discovery формируются ESPHome.
Уже сохранённые брокером discovery-сообщения не удаляются при снятии checkbox.

На `/modbus` checkbox RTU и TCP независимы. Изменения действуют сразу; существующие
TCP-соединения закрываются. Скорости:9600/19200/38400/57600/115200, формат8E1.
Unit1–247. Выключенный RTU не отвечает, выключенный TCP не слушает502.
Диагностические флаги2479 отражают выбранные состояния транспортов.
Ни один из checkbox не разрешает UART автоматически.

Для первоначального Wi-Fi остаётся ESPHome captive portal на8080. Подключившись
к Samsung-Setup, открыть `http://192.168.4.1:8080/`; ссылка «Настройка Wi-Fi (AP)»
также ведёт туда. Основной портал настроек на80 доступен и при активной AP.

## Обновление

Источник: `https://raw.githubusercontent.com/dk-1983/Samsung-ESP32-MQTT-Modbus/main/releases/stable.json`.
Профиль: `samsung-s3-n16r8-v1`. Образ загружается из Releases этого же репозитория.
Автоматическая установка по умолчанию разрешена; checkbox запрещает
установку, но оставляет проверку. Проверка после старта примерно через минуту,
далее раз в6часов с небольшим случайным сдвигом. Нужны сеть и синхронизированное время.

Перенесены ECDSA P-256 подпись манифеста, HTTPS с проверкой сертификата, проверка
профиля/размера/SHA256/ESP32-S3, отдельный OTA-раздел, подтверждение загрузки и откат.
Новая загрузка считается здоровой после45с работы локальных служб и сети;
сохранённый trial позволяет вернуться к предыдущему слоту при следующем неудачном
запуске или по таймауту. Это пока перенесённый код, а не выполненный тест отката Samsung.
Ключ доверия — открытый ключ издателя 4vrs; закрытый ключ не публикуется.
Профиль и URL Samsung проверяются: манифест другого устройства не принимается.

Локальный OTA и GitHub worker согласованы: worker ждёт разрешения основного цикла;
на время записи GitHub локальный OTA приостановлен. Настройки транспортов во время
GitHub операции не изменяются; запрет обновления можно применить и во время загрузки.

## Релиз

1. Первую0.4.0 установить локальной приватной сборкой, чтобы сохранить персональные
   пароли в NVS. Публичный OTA не предназначен для первичной прошивки пустой платы.
2. В GitHub запустить workflow `Prepare public OTA artifact`. Он использует только
   `release.defaults.yaml`, проверяет чистоту дерева и формирует OTA-образ без личных паролей.
3. Скачать artifact, проверить на стенде. Установить зависимости `requirements-release.txt`.
4. Подписать: `python tools/sign_release.py --build <artifact-directory> --key <private-P256.pem> --out releases/stable.json`.
   Инструмент проверяет соответствие ключа открытому ключу прошивки.
5. При публикации создать тег/Release `v<version>`, загрузить OTA-файл из artifact,
   затем опубликовать подписанный `releases/stable.json` в main.

Стабильный релиз 0.5.0 содержит готовый OTA-бинарник и подписанный манифест обновления. Публичный бинарник предназначен для уже настроенного контроллера.

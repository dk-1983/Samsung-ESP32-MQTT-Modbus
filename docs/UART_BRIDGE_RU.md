# Экспериментальный прозрачный UART-мост

## Закреплённая разводка Samsung, 26.09.2026

По результатам проверки и решению владельца мост закреплён на соседних GPIO15–18
для удобства разводки платы и шлейфа. Основная сторона: RX18/TX17;
штатная плата дисплея/Wi-Fi: RX15/TX16. Modbus перенесён на RX8/TX9, DE=/RE GPIO21.
Все номера здесь — GPIO ESP32, не физические номера контактов модуля.

После загрузки моста RX15/TX16 появился обмен в обе стороны: за первые ~30 секунд
2899 байтов со стороны основной платы и 2309 со стороны Wi-Fi были приняты и
переданы противоположному UART-драйверу. Видны штатные запросы и ответы.
Пользователь подтвердил появление значка Wi-Fi. Управление SmartThings отдельно
ещё не подтверждено; эти проверки не гарантируют отсутствие потерь.

Основная конфигурация — `samsung-bridge.yaml`, версия 0.4.7-bridge.
Она пересылает байты без собственных запросов, ACK, инициализации или команд.
MQTT/Modbus в этой сборке ещё отсутствуют. `samsung-s3.yaml` уже использует новые
выводы Modbus, но пока остаётся отдельной управляющей сборкой без прозрачного моста.
Не загружать старые релизы с RS485 на GPIO15/16 в эту проводку.

## Подключение при снятом сетевом питании

Разорвать обе линии между основной и штатной платами. Названия №9/№10
относятся к CN1 кондиционера, а номера GPIO — отдельные обозначения выводов ESP32.

| Откуда | Куда |
|---|---|
| Основная плата: провод CN1 №10, TX | Через согласование 3,3 В на GPIO18 RX |
| GPIO16 TX ESP32 | Вход штатной платы, ранее соединённый с CN1 №10 |
| Выход штатной платы, ранее соединённый с CN1 №9 | Через отдельное согласование 3,3 В на GPIO15 RX |
| GPIO17 TX ESP32 | Основная плата: провод CN1 №9, RX |

Общая земля. №11, питание штатной платы и остальные соединения остаются штатными.
Не объединять TX ESP32 и штатный TX. GPIO8/9 теперь предназначены для Modbus.
Выходы ESP32 имеют уровень 3,3 В; пригодность нового TX для входа штатной платы
ещё проверяется на стенде. Не подавать на входы ESP32 несогласованный сигнал 5 В.

## Поведение и ограничения

UART A: RX18/TX17 (основная плата), UART B: RX15/TX16 (штатная плата), 9600 8N1.
Каждый принятый байт пересылается на TX противоположного UART до записи в журнал.
Не фильтруются неизвестные пакеты и не пересчитываются контрольные суммы.
Чтение чередуется порциями до 48 байтов; это не границы протокольных кадров.
HTTP, Wi-Fi, загрузка и OTA могут вносить задержки. Нет аппаратного обхода при
сбое или отключении ESP32, нет гарантии отсутствия потерь или сохранения межбайтовых пауз.
Счётчики forwarded_a/b означают байты, переданные UART-драйверу, а не подтверждение
приёма другой платой. rx17_bytes в JSON оставлено для совместимости: в мосте это RX15.

Порт 8080: переключатель UART bridge forwarding, включён при каждой загрузке.
Выключение прекращает пересылку, поступающие байты продолжают регистрироваться
и не воспроизводятся после включения. Это разрывает связь штатных плат.
Порт 80: журнал; `/capture` сообщает bridge=true, passive=false и состояние forwarding.
Защищённый `/diagnostics` читает состояние драйверов, скорость, уровень RX,
маршрутизацию входов GPIO matrix и режимы четырёх выводов. Он не меняет сигналы.
Уровень RX — моментальный логический отсчёт, не измерение напряжения или осциллограмма.
В каждом элементе `uart` также есть `edges` — счётчик изменений уровня RX через
GPIO-прерывания, независимо от UART-декодера; `edge_error: 0` подтверждает успешную
установку обработчика. Счётчик стартует после инициализации, сбрасывается при
перезапуске и не является гарантированно точным логическим анализатором.
Растущий `edges` при нулевом `received` указывает на активность без приёма байтов;
нулевой счётчик означает отсутствие зарегистрированных переходов, а не доказательство
отсутствия аналоговых колебаний или исправности внешнего соединения.

Диагностический параметр компонента `monitor_only: true` запрещает пересылку,
переводит GPIO17/16 во входы без подтяжек и выполняет внутренний loopback-тест
каждого UART только после проверки, что оба выхода отключены. В `/diagnostics`
`loopback: [1,1]` означает успешный внутренний тест обоих UART; `-1` — не запускался,
`-2` — не удалось включить loopback, `0` — несовпадение принятых данных.
Внутренний тест не проверяет внешние выводы, согласование уровней и штатные платы.
Этот режим не является рабочим мостом. В обычной сборке параметр отсутствует (false).

### Архивные диагностические конфигурации

Следующие варианты проверяли прежние предполагаемые GPIO8/9. При текущей
проводке они не слушают штатную плату; их молчание не доказывает отсутствие обмена.

`samsung-bridge-observe.yaml` — отдельный приёмный тест прежних выводов:
UART0 слушает GPIO18, UART1 — GPIO8, UART2 — GPIO9. TX не назначены;
GPIO17 и GPIO9 явно переводятся во входы без подтяжек. Пересылки и внутреннего
loopback-теста нет. Временное использование UART2 не меняет GPIO15/16/21;
Modbus в этой диагностической сборке отсутствует. `/diagnostics` показывает
три приёмника, журнал помечает новые порции GPIO9. Параметр `rx_c` запрещён
вне режима `bridge: true, monitor_only: true`.
Для возврата пересылки загрузить обычную `samsung-bridge.yaml`.
В первом трёхканальном тесте UART2 сообщил ошибку чтения baud rate, поэтому
его отсутствие декодированных пакетов нельзя считать достоверным результатом.
`samsung-bridge-observe9.yaml` проверяет GPIO9 через UART1 вместо UART2,
также без передачи. Диагностические варианты observe используют одну папку
сборки; при переключении требуется перегенерация CMake. Обычный мост имеет
отдельную папку и сохраняет свой бинарник для возврата.

```text
python tools/capture_uart.py --secrets secrets.yaml --allow-bridge --seconds 600 --output work/bridge.jsonl
```

Сначала проверить на мосте дисплей, IR-пульт и штатное приложение. Собственные
команды потребуют отдельного диспетчера транзакций и проверки конфликтов счётчиков;
в этой сборке их нет. Samsung Cloud не отключается самим мостом.
Исключение для диагностики молчащей шины: авторизованный POST `/probe/main-power`
с заголовком `X-Samsung-Probe: read-only` отправляет один FE1202, поле 02, counter E1.
Он разрешён только после 20 секунд работы, при включённом мосте без зарегистрированного
обмена/фронтов (кроме одного стартового байта на B), не более раза за загрузку.
Это чтение, без инициализации и записи настроек. Автоматически не отправляется.
`probe_sent` означает отправку драйверу, не подтверждение кондиционером.

26.09.2026 этот запрос получил FE1203/02=0F с тем же counter E1 на GPIO18:
19 принятых и переданных на противоположный UART байтов, 62 GPIO-перехода.
Подтверждён путь ESP32 TX17 → основная плата → RX18. В том опыте TX9/RX8 не были физически подключены к штатной плате;
последующий тест RX15/TX16 восстановил штатный обмен, как описано выше.
Не загружать эту сборку в текущую схему пассивного сниффера с общим GPIO17/TX.
Возврат к рабочей прошивке также требует соответствующей перекоммутации.

Основание: локальные двухканальные записи UART и тест разрыва №10 2026-09-26.
Дисплей/пульт сохранили работу без подачи основной TX-линии на штатную плату;
это не доказывает функцию №11 и не определяет весь внутренний путь IR.

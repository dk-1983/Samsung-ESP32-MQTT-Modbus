# Стенд до разборки Samsung

Сначала отладить ESP32 и все внешние интерфейсы без кондиционера. Нужны:

- ESP32-S3 N16R8 с нашей прошивкой и USB-питанием.
- Отдельный USB-UART адаптер **с логическими уровнями 3,3 В** для эмуляции кондиционера.
- ПК, домашняя Wi-Fi-сеть; для MQTT — ваш локальный брокер.
- Для отдельного испытания RTU — USB-RS485 и имеющийся RS485-трансивер платы.

## Схема UART-стенда

| USB-UART эмулятора | ESP32 |
|---|---|
| TXD, 3,3 В | GPIO18, Samsung RX |
| RXD, 3,3 В | GPIO17, Samsung TX |
| GND | GND |
| VCC | Не подключать: ESP32 питается отдельно от USB |

Это подключение прямо к логической стороне ESP32, не к неизвестному разъёму кондиционера.
Если на плате между этими GPIO и разъёмом уже стоят преобразователи/оптопары, точки подключения
выбирать с учётом схемы платы. TTL-UART и RS485 A/B не соединять друг с другом.
На этом этапе кондиционер вообще не подключается.

COM-порт встроенного USB ESP32 используется для прошивки; COM-порт отдельного USB-UART — для эмулятора.
Это разные порты. Для просмотра журнала удобно использовать веб-пульт; UART0-лог при необходимости
выведен отдельно на GPIO43 (115200 8N1).

## Последовательность

1. Собрать/прошить только тестовую ESP32, настроить Wi-Fi через Samsung-Setup. Открыть её веб-пульт.
2. Запустить `python tools/uart_simulator.py --port COM8` подходящим Python из `work/venv/Scripts`.
3. Выключить UART transmission в веб-пульте (в 0.4.2 она включена при запуске). Дождаться актуальных данных: off, cool, 24 °C, room 25 °C, auto fan.
   RX растёт, TX=0. Попытка управления из веб/MQTT не должна менять эмулятор.
4. Выполнить `python tools/bench_check.py --host IP_ESP32`: проверяются TCP502 и обратная связь,
   никаких команд записи по умолчанию нет.
5. Включить UART transmission experimental. Проверить один запрос температуры из веб-пульта;
   результат должен пройти pending → confirmed. Не запускать несколько источников команд одновременно.
6. Выполнить `python tools/bench_check.py --host IP_ESP32 --exercise`: скрипт меняет температуру,
   ждёт подтверждения через UART, затем возвращает исходную. Только для стенда с эмулятором.
7. Проверить те же команды через MQTT. Передачу UART включать только локально в веб.
8. Остановить эмулятор: через 30 секунд AC feedback fresh погаснет, чтение состояния по Modbus даст 0x0B.
   Перезагрузить ESP32: в 0.4.2 передача UART должна включиться автоматически.

Скрипты подготовлены; физическое выполнение этих испытаний на плате ещё не подтверждено.

## RS485 / Modbus RTU

Логическая сторона трансивера: DI ← GPIO9, RO → GPIO8, DE и /RE ← GPIO21 (совместное управление).
Логические уровни трансивера должны соответствовать ESP32. Шинная сторона A/B → USB-RS485,
расположение A/B сверять по обозначениям конкретных устройств; для неизолированного короткого стенда
предусмотреть сигнальный общий провод. Питание, развязка и терминаторы — по уже имеющейся схеме платы.

На ПК любой Modbus master: 9600, 8E1, адрес 1. FC03, start 52, count 4 → питание/режим/вентилятор/вертикальное качание.
FC06, register 58, value 230 → уставка 23 °C; FC04 register 2478 → результат. Карта в MODBUS.md.
RTU и TCP используют один командный слот; при pending второй источник получает 06 busy.

## Что стенд докажет

Он проверяет прошивку, GPIO UART, драйвер RS485, веб/MQTT/Modbus и обработку обратной связи.
Он **не докажет**, что AR24BSFCMWKNER использует этот UART-профиль или что электрический интерфейс
готовой платы совместим с разъёмом Samsung. После подготовки стенда при первом доступе к кондиционеру
нужны фото плат/разъёмов и пассивная запись обмена штатного Wi-Fi, затем уточнение драйвера.

# Home Assistant через MQTT Discovery

[English](HOME_ASSISTANT.md)

Samsung-ESP32 публикует MQTT Discovery через ESPHome. Отдельная интеграция Samsung,
Hub, HACS или ручное описание сущностей в YAML не нужны.

## Подключение

1. В Home Assistant добавьте штатную интеграцию MQTT: Настройки → Устройства
   и службы → Добавить интеграцию → MQTT. Укажите свой брокер.
2. Откройте `http://<IP-контроллера>/mqtt`. Введите тот же брокер, порт (обычно 1883),
   логин и пароль. Включите MQTT и Home Assistant Discovery.
3. Сохраните настройки. В версии 0.4.2 плата автоматически перезагрузится через
   2 секунды для применения подключения. Пустое поле пароля сохраняет прежний пароль;
   отдельный checkbox удаляет его. После сохранения пароль не показывается в браузере.
4. Дождитесь подключения. В интеграции MQTT появляется устройство
   **Samsung-ESP32-MQTT-Modbus** с климатом **Air conditioner**, настройками и диагностикой.
5. UART включается при каждой загрузке 0.4.2. Переключатель **UART transmission
   experimental** в веб-пульте позволяет отключить передачу. **AC feedback fresh**
   показывает свежесть обратной связи кондиционера.

Если устройство не появляется, проверьте авторизацию, совпадение брокера в HA
и контроллере, права MQTT на публикацию/подписку и префикс обнаружения `homeassistant`.
Сохранение настроек само по себе не подтверждает подключение к брокеру.

## Топики и доступность

- Discovery: `homeassistant/<тип>/samsung-s3/<сущность>/config`.
  Идентификаторы сущностей основаны на MAC контроллера; сущности объединены в устройство.
- Рабочий префикс настраивается, по умолчанию `samsung-s3`. Топики конкретных
  команд и состояний указаны в Discovery-сообщениях.
- Конфигурации retained: брокер сохраняет их и передаёт при подключении HA.
  Отдельного обработчика `homeassistant/status` в текущей прошивке нет.
- MQTT availability показывает соединение контроллера; свежесть UART отдельно
  показывает **AC feedback fresh**. Соединение с брокером не доказывает связь с AC.
- Отключение Discovery не удаляет уже сохранённые брокером конфигурации.

Подключение с авторизацией, восстановление MQTT после перезагрузки и получение
данных на стенде проверены. Экспериментальные функции требуют аппаратной проверки.
Запрошенное значение не выдаётся за полученное от кондиционера состояние.

[Официальная документация MQTT Home Assistant](https://www.home-assistant.io/integrations/mqtt/).

## Собственный MQTT-брокер без Home Assistant

Контроллер работает с самостоятельным MQTT-брокером; Home Assistant для этого не нужен.
На странице `/mqtt` укажите адрес брокера, порт, учётные данные и рабочий префикс.
Клиентом может быть собственный сервер, Node-RED или другая система автоматизации.

В MQTT используются топики и полезная нагрузка сообщений, а не адреса регистров Modbus.
Перечень MQTT-интерфейсов конкретной прошивки можно получить прямо с брокера:

1. Включите MQTT и Discovery в контроллере. Публикация Discovery не требует установленного Home Assistant.
2. Подпишитесь MQTT-клиентом на `homeassistant/#` и найдите конфигурации своего устройства по MAC / `device`.
3. Из JSON-конфигураций возьмите топики команд и состояний, допустимые режимы и значения,
   шаблоны обработки и availability. В конфигурациях могут использоваться сокращённые имена полей.
4. Подпишитесь также на `<префикс>/#` для наблюдения рабочих сообщений.
   По умолчанию это `samsung-s3/#`; фактические топики берите из конфигураций Discovery.

Discovery служит машиночитаемым перечнем сущностей; брокер хранит retained-конфигурации.
После настройки своего клиента Discovery можно отключить — рабочий MQTT остаётся включённым.
Отключение Discovery само по себе не удаляет сохранённые конфигурации.

Примеры команд при стандартном префиксе:

| Действие | Топик | Сообщение |
|---|---|---|
| Включить кондиционер | `samsung-s3/button/ac_power_on/command` | `PRESS` |
| Выключить кондиционер | `samsung-s3/button/ac_power_off/command` | `PRESS` |

Команды отправляются без retain. Выполнение проверяется по обратной связи кондиционера;
публикация сообщения и подтверждение брокера сами по себе не означают исполнение.

## Логирование сырых UART-кадров (0.5.1)

Полные кадры публикуются в отдельных MQTT-топиках без Discovery-сущностей
Home Assistant и без retain:

| Топик | Содержимое |
|---|---|
| `<prefix>/diagnostics/uart/rx` | Последний принятый кадр, полный HEX с пробелами |
| `<prefix>/diagnostics/uart/tx` | Последний отправленный кадр, полный HEX с пробелами |
| `<prefix>/diagnostics/uart/write_reply` | Последний ответ на запись, полный HEX с пробелами |

Для записи журнала подпишитесь на `<prefix>/diagnostics/uart/#`.
Используется настроенный префикс, в том числе пользовательский. RX/TX обновляются
каждые 2 секунды, ответ на запись — каждую секунду. Это снимки последних кадров,
а не полная запись шины: промежуточные кадры могут смениться между публикациями;
при отсутствии MQTT сообщения не накапливаются. Полные кадры также остаются
в локальной диагностике и веб-журнале.

При подключении MQTT прошивка удаляет три старые retained-конфигурации Discovery
и сохранённые состояния. Управление климатом, расшифрованные значения и остальные
диагностические сущности остаются в Home Assistant. Созданные вручную датчики
сырых кадров нужно удалить вручную. Ограничение состояния HA в 255 символов
не применяется к новым топикам логирования: они не объявляются сущностями.

## Журнал запуска и восстановления (0.5.2)

Контроллер публикует JSON в `<prefix>/diagnostics/boot` с QoS 1, без retain:
`boot_ready`, `mqtt_reconnected` и `ac_connection_restored`.
Поля: `version`, `boot_id` (не меняется при переподключении MQTT), `uptime_s`,
`controller_ready`, `boot_confirmed` и `ac_ready`.

Для `boot_ready` нужны Wi-Fi, MQTT, работающий веб-сервер, исправное хранилище
настроек и учётных данных, доступный сервис обновлений и подтверждённая загрузка
прошивки. Эти условия должны сохраняться 5 секунд. После OTA подтверждению загрузки
предшествуют 45 секунд проверки локальной работоспособности. Ожидание ответа
кондиционера не блокирует сообщение: `ac_ready: false` означает, что контроллер
готов, но связь с кондиционером ещё не готова. После её устойчивого восстановления
поступает `ac_connection_restored`. Выключенное состояние кондиционера само по себе
не означает отсутствия связи.

Вставьте [пример автоматизации](../examples/home-assistant-boot-log-ru.yaml) в
YAML-редактор новой автоматизации Home Assistant. Замените `samsung-s3` на свой
префикс MQTT. Дополните `configuration.yaml`, не дублируя существующий блок logger:

```yaml
logger:
  logs:
    samsung_controller: info
```

Примените настройки logger перезагрузкой/перезапуском Home Assistant по необходимости.
Автоматизация пишет об успешном запуске/восстановлении через `system_log.write`
с уровнем INFO. Эти записи видны в полном журнале, а не в кратком списке ошибок
и предупреждений. События не сохраняются с retain: перезапуск Home Assistant
не повторяет сообщение о старой загрузке. Отключённый подписчик может пропустить
событие; QoS 1 допускает дубликаты. События дополняют MQTT availability и свежесть
ответов кондиционера, но не подавляют другие предупреждения интеграции.

[Home Assistant System Log](https://www.home-assistant.io/integrations/system_log/).
